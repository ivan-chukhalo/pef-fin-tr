# Personal Finance Tracker: інструкції для асистента (Codex)

Це персональний вебзастосунок для обліку доходів, витрат, рахунків і переказів. Користувач один (власник), публічної реєстрації немає. Усі тексти інтерфейсу українською. Тільки темна тема.

## Стек
- React + Vite + TypeScript
- Tailwind CSS
- React Router
- Supabase (PostgreSQL, вхід через email і пароль, Row Level Security)
- Recharts (графіки)
- Хостинг: Netlify або Vercel, репозиторій на GitHub

## Головні правила (обов'язкові)
1. **Гроші зберігаємо в копійках** (цілі числа), ніколи в гривнях з дробовою частиною.
2. **Сума в гривнях фіксується при збереженні транзакції.** Зміна курсу не перераховує історію.
3. **Переказ — окрема таблиця `transfers`**, а не транзакція. Переказ не потрапляє в доходи й витрати.
4. **Баланс рахунку не зберігається окремим полем.** Він рахується: початковий баланс + доходи − витрати ± перекази.
5. **Категорії не видаляються**, лише приховуються (`is_hidden`). Перейменування дозволене.
6. **Кожна таблиця має `user_id`**, і на кожній увімкнено Row Level Security.
7. **MVP: дата транзакції і переказу не може бути пізнішою за сьогодні.** Майбутні операції, прогноз і повторювані операції належать до версії 1.1 і не реалізуються раніше за свій крок у плані.
8. **Підкатегорій у MVP немає.** Не додавати їх без окремого запиту.
9. **Без кнопки «Вийти» і без реєстрації.** Вхід один раз на пристрій.
10. **Секрети не комітимо.** Ключі Supabase зберігаються в `.env.local`, цей файл є в `.gitignore`. Не вставляй ключі в код, документи чи коміти.

## Документи проєкту
- `docs/mvp.md`: що входить у MVP і що відкладено
- `docs/screens-and-scenarios.md`: сторінки, навігація, сценарії
- `docs/database.md`: схема таблиць, зв'язки, формули балансу

- `docs/progress.md`: поточний крок і журнал

## Як працювати
- Перед початком роботи прочитай `docs/progress.md`, а потім документ, який стосується поточного кроку.
- Працюй лише над поточним кроком. Не переходь до наступного, поки не виконано критерій «Готово, коли» з `development-plan.md`.
- Перед будь-якою зміною схеми бази покажи SQL і поясни, що зміниться. Чекай підтвердження власника.
- Перш ніж змінювати код, що працює з балансами, переказами або правилами доступу, поясни, що саме зміниться.
- Пояснюй прості речі простою мовою: власник — початківець у розробці, але знає JavaScript, Git і GitHub.
- Один крок плану — одна серія комітів з понятними описами.
- Після завершення кроку онови `docs/progress.md`.
