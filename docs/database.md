# Схема бази даних (PostgreSQL у Supabase)

Загальні правила:
- Гроші зберігаються в **копійках** (цілі числа).
- Кожна таблиця має `user_id`, на кожній увімкнено Row Level Security (доступ лише власнику).
- Ідентифікатори — UUID.
- Дати — тип `date`, часові мітки створення і зміни — `timestamptz`.

## Таблиці (MVP)

### accounts (рахунки)
| Поле | Тип | Опис |
|---|---|---|
| id | uuid | первинний ключ |
| user_id | uuid | власник (посилання на auth.users) |
| name | text | назва, наприклад «Картка 1», «Готівка» |
| type | text | `card` або `cash` |
| initial_balance_kop | bigint | початковий баланс у копійках |
| is_hidden | boolean | приховано (за замовчуванням false) |
| created_at | timestamptz | |

Баланс не зберігається. Він рахується з `initial_balance_kop`, `transactions` і `transfers`.

### categories (категорії)
| Поле | Тип | Опис |
|---|---|---|
| id | uuid | первинний ключ |
| user_id | uuid | власник |
| name | text | назва (можна змінювати) |
| type | text | `income` або `expense` |
| is_hidden | boolean | приховано (за замовчуванням false) |
| created_at | timestamptz | |

Поля «стандартна» немає. Видалення категорій у MVP не передбачено.

### transactions (доходи і витрати)
| Поле | Тип | Опис |
|---|---|---|
| id | uuid | первинний ключ |
| user_id | uuid | власник |
| account_id | uuid | посилання на accounts |
| category_id | uuid | посилання на categories |
| type | text | `income` або `expense` |
| date | date | дата операції; у MVP не може бути пізніше сьогодні |
| currency | text | `UAH` або `USD` |
| amount_original_kop | bigint | сума в оригінальній валюті, копійки (або центи) |
| rate | numeric | курс на дату операції (для UAH дорівнює 1) |
| amount_uah_kop | bigint | сума в гривнях, копійки, фіксується при збереженні |
| purchase_name | text | необов’язкова назва покупки, лише для витрат |
| comment | text | необов'язково |
| created_at | timestamptz | |
| updated_at | timestamptz | |

Примітка: для долара `amount_uah_kop` = `amount_original_kop` × `rate`, округлене до копійки при збереженні.

### transfers (перекази)
| Поле | Тип | Опис |
|---|---|---|
| id | uuid | первинний ключ |
| user_id | uuid | власник |
| from_account_id | uuid | посилання на accounts |
| to_account_id | uuid | посилання на accounts |
| date | date | дата переказу; у MVP не може бути пізніше сьогодні |
| amount_uah_kop | bigint | сума в гривнях, копійки |
| comment | text | необов'язково |
| created_at | timestamptz | |

Перевірка: `from_account_id` і `to_account_id` мають бути різними.

## Зміни для версії 1.1

### Нові поля в transactions і transfers
| Поле | Тип | Опис |
|---|---|---|
| status | text | `planned` (заплановано) або `confirmed` (підтверджено). Для існуючих записів — `confirmed` |
| template_id | uuid, може бути порожнім | майбутнє поле в `transactions` для операцій із шаблону `recurring_templates` |

Майбутня дата дозволена для операцій зі статусом `planned`. Для `confirmed` дата має бути не пізніше сьогодні за київським часом. Фактичні баланси й підсумки враховують тільки `confirmed`.

### Нова таблиця recurring_templates (шаблони повторюваних операцій)
| Поле | Тип | Опис |
|---|---|---|
| id | uuid | первинний ключ |
| user_id | uuid | власник |
| type | text | `income` або `expense` |
| account_id | uuid | посилання на accounts |
| category_id | uuid | посилання на categories |
| currency | text | `UAH` або `USD` |
| amount_original_kop | bigint | сума за одне повторення |
| rate | numeric | курс для планових операцій |
| comment | text | необов'язково |
| frequency | text | `weekly` (щотижня) або `monthly` (щомісяця) |
| start_date | date | дата першого повторення; наступні — через тиждень або місяць у той самий день |
| occurrences | integer | скільки разів повторювати (від 1 до 120) |
| created_at | timestamptz | |

Правила:
- Створення шаблону одразу створює `occurrences` записів у `transactions` зі статусом `planned` і `template_id`.
- Якщо в місяці немає потрібного дня (наприклад, 31-го), операція припадає на останній день місяця.
- Зміна шаблону оновлює лише записи зі статусом `planned`. Підтверджені записи не змінюються.
- Видалення шаблону видаляє лише `planned` записи. Підтверджені лишаються в історії, а `template_id` у них обнуляється.
- Підтвердження: статус стає `confirmed`, можна змінити суму і курс.

Відкрите питання: регулярні перекази в 1.1 не передбачені (лише одноразові майбутні перекази).

## Зв'язки
- accounts 1 → багато transactions
- categories 1 → багато transactions
- accounts 1 → багато transfers (як джерело, `from_account_id`)
- accounts 1 → багато transfers (як отримувач, `to_account_id`)
- recurring_templates 1 → багато transactions (версія 1.1)
- auth.users 1 → багато рядків у кожній таблиці через `user_id`

## Формула балансу рахунку (MVP)
```
баланс = initial_balance_kop
       + сума доходів на рахунку
       − сума витрат на рахунку
       + сума переказів, де рахунок — отримувач
       − сума переказів, де рахунок — джерело
```

## Формула прогнозу на дату X (версія 1.1)
```
прогноз на X = баланс на сьогодні (тільки підтверджені операції)
             + заплановані доходи з датою в (сьогодні, X]
             − заплановані витрати з датою в (сьогодні, X]
             ± заплановані перекази з датою в (сьогодні, X]
             + прострочені заплановані операції (дата ≤ сьогодні, статус planned)
```
Прострочені операції враховуються в прогнозі, доки їх не підтвердять або не видалять. Вони виводяться в окремому списку з позначкою «прострочено».
